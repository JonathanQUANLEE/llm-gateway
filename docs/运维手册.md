# 运维手册（渠道验收 + 工单排障 FAQ）

## 一、部署与重置

```bash
docker compose up -d          # 启动/更新
docker compose ps             # 状态
docker compose logs -f new-api    # 网关日志（排障第一现场）
docker compose restart new-api   # 重启网关
```

- 后台：http://localhost:3000，管理员 root（密码见部署记录，可在后台改）
- 生产要点：SESSION_SECRET 多实例必须一致；`.env` 不要提交 git；Nginx 挂 `nginx/gateway.conf`

## 二、渠道接入验收清单（每接一个上游过一遍）

| # | 步骤 | 怎么做 | 通过标准 |
|---|---|---|---|
| 1 | 连通性 | 非流式 curl 调一次（smoke_test 或手撸） | 200，延迟正常 |
| 2 | 模型清单 | `curl -H "Authorization: Bearer sk-xxx" .../v1/models`，逐个模型真调 | 与供应商给的列表一致 |
| 3 | 流式质量 | `channel_probe.py`，看 TTFT / chunk 数 / [DONE] | TTFT 正常、收尾完整 |
| 4 | 小并发 | 10 并发循环调用，看成功率 | 成功率 >99%，无 5xx |
| 5 | 灰度放量 | 后台挂渠道，低权重；记台账 | 观察一段时间稳定后提权重 |

**台账字段**：日期 / 渠道名 / 类型 / 倍率 / 限额 / 测试结论 / 备注。每单必记：做事有台账、可复盘。

后台操作：**渠道 → 添加渠道** → 选类型（OpenAI 兼容上游都选 OpenAI）→ 填 Base URL + 上游 Key + 模型列表 → 保存 → 可用性里点"测试"。

## 三、工单排障 FAQ（按现象查）

### Q1：客户说 401 / 无效令牌
1. 让客户发完整报错（含 request id）；
2. 后台 → 令牌：核对 key 是否复制完整（常见：带空格/截断）、状态是否启用、额度是否用尽、是否过期；
3. 核对令牌分组是否有该模型权限；
4. 仍不行 → 拿 request id 查日志。
**本网关实测返回体**：`401 {"error":{"message":"Invalid token (request id: ...)","type":"new_api_error"}}`

### Q2：客户说"模型不可用"
1. curl 复现；
2. 本网关表现：`503 code:"model_not_found"`，消息 `No available channel for model xxx under group default`；
3. 两种可能：模型没配在任何渠道上（查渠道模型列表）／ 所有可用渠道都挂了（查渠道状态，测试按钮）；
4. 修复：补配模型映射，或启用/新增渠道。

### Q3：客户说被 429 限流
1. 看返回体判断是谁的限额：网关文案（new_api_error）= 客户级；上游原始报错 = 渠道级；
2. 客户级 → 后台调该令牌/用户的 RPM、TPM 限额（或告知客户套餐规则）；
3. 渠道级 → 提升渠道权重分流、加渠道、或错峰。

### Q4：流式卡住 / 假死 / 攒一大块才吐
按链路分段定位：
1. 客户端：他的代码是不是没按行读 SSE；
2. 网关：日志里请求是否正常转发、上游是否在持续发块；
3. **Nginx：默认 proxy_buffering 会攒流！** `nginx/gateway.conf` 已配置 `proxy_buffering off` + `proxy_read_timeout 300s`；
4. 上游 TTFT 慢 → 用 channel_probe.py 实测，慢就切渠道。

### Q5：扣费 / 用量疑问
1. 后台 → 日志：按时间 + 用户 + 模型筛出该客户调用记录；
2. 核对每次的 prompt_tokens / completion_tokens（长上下文是扣费大头，客户常忽略历史消息也在计费）；
3. 倍率对不对：模型倍率 × 分组倍率；1 美元 = 500,000 quota；
4. 有争议的单次调用 → 用 request id 精确复盘。

### Q6：整体慢
1. channel_probe.py 批量测各渠道 TTFT / 总延迟；
2. 慢渠道降权重或禁用；
3. 观察网关自身资源（`docker stats`），网关 CPU 不是瓶颈的话问题都在上游和网络。

## 四、常用命令速查

```bash
# 网关自身状态
curl http://localhost:3000/api/status

# 列出模型（OpenAI 兼容）
curl -H "Authorization: Bearer sk-xxx" http://localhost:3000/v1/models

# 非流式调用
curl -sS http://localhost:3000/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" -H "Content-Type: application/json" \
  -d '{"model":"MODEL","messages":[{"role":"user","content":"ping"}],"max_tokens":20}'

# 流式调用（观察 data: 分块和结尾 data: [DONE]）
curl -N http://localhost:3000/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" -H "Content-Type: application/json" \
  -d '{"model":"MODEL","messages":[{"role":"user","content":"从1数到5"}],"stream":true}'

# 渠道批量测活/测速（TTFT）
python scripts/channel_probe.py --config scripts/channels.json

# 网关冒烟 + 故障演练（401/503/200/流式 全覆盖）
python scripts/smoke_test.py --key sk-xxx --model MODEL
```
